# CLAUDE.md — правила работы агента в этом репозитории

Конвейер: входящие заявки → Claude (structured outputs) → CSV/XLSX. Что и зачем — `README.md`;
как меряем качество — `evals/README.md`; показ за три минуты — `docs/walkthrough.md`.

## Границы

- Схема результата — `lead_pipeline/schema.py` (`LeadAnalysis`). Модель заполняет схему через
  `client.messages.parse`; разбора текста «с JSON внутри» нет и не должно появиться.
- Промпты — только файлы `prompts/lead_analysis.vN.md` с frontmatter (`version`, `model`, `changelog`).
  Правка промпта = новая версия; старые версии не трогать, потому что номер версии пишется в каждую
  строку результата и прошлые прогоны должны воспроизводиться.
- Данные синтетические (`lead_pipeline/generator.py`, `evals/golden.jsonl`). Реальные обращения и
  телефоны в репозиторий не класть.
- Интеграции (Telegram, Google Sheets) выключены по умолчанию и не нужны ни для тестов, ни для прогона.

## Как проверять

- `pytest` — без сети, провайдер `fake`. `evals/test_golden_accuracy.py` держит порог:
  категории ≥ 90 %, срочность ≥ 80 %.
- Перед изменением промпта: `LEAD_EVAL_PROVIDER=anthropic pytest evals/` (ключ в окружении);
  новые цифры — в таблицу «Результаты» в README с датой прогона.
- Новый спорный случай: сначала пример в `evals/golden.jsonl` с ожидаемой разметкой, потом правило в промпте.

## Структура

`schema.py` → `prompts.py` → `llm.py` (провайдеры) → `pipeline.py` (параллельно, порядок сохраняется) →
`export.py` (CSV, XLSX) и `report.py` (консоль, Telegram) → `notify.py`. Оценка — `evalrun.py`.
Ошибка провайдера на одной заявке — поле `error` в строке результата, конвейер не падает.
