# Экскурсия за 3 минуты

Что показать, если на проект есть три минуты. Подготовка один раз: `pip install -r requirements.txt`,
в `.env` задан `ANTHROPIC_API_KEY`, `pytest` зелёный, терминал открыт в папке проекта, рядом файл
`out/leads.xlsx` от прошлого прогона (чтобы не ждать).

## 1. Задача (20 секунд)

«Заявки приходят письмами, с сайта и из чата, в свободной форме. Конвейер определяет
категорию и срочность, достаёт имя, телефон, услугу, дату и бюджет и кладёт всё в таблицу.
Качество измеряется на размеченном наборе, промпты версионируются».

## 2. Живой прогон (60 секунд)

```bash
python -m lead_pipeline run --input data/sample.jsonl --out out/ --limit 20
```

Показать отчёт в консоли: распределение по категориям и срочности, блок «Срочные
обращения» с телефонами. Открыть `out/leads.xlsx`: фильтры, подсветка срочности, лист «Сводка».

## 3. Как это устроено (60 секунд)

- `lead_pipeline/schema.py` — Pydantic-модель `LeadAnalysis`: категории и срочность как
  `Literal`, поля либо значение, либо `null`. Из неё же получается JSON-схема.
- `lead_pipeline/llm.py` — `client.messages.parse(..., output_format=LeadAnalysis)`:
  structured outputs, ответ гарантированно по схеме, без разбора «текста с JSON внутри».
  Рядом заглушка на правилах — для тестов и работы без ключа.
- `prompts/lead_analysis.v2.md` — промпт файлом: определения категорий, правила спорных
  случаев, нормализация полей. Версия пишется в каждую строку результата.
- `evals/golden.jsonl` + `evals/test_golden_accuracy.py` — 30 размеченных примеров, порог
  точности в тесте. На Claude Haiku 5.5: v1 — 97 %, v2 — 100 % по категориям.

## 4. Качество и цена (40 секунд)

```bash
python -m lead_pipeline eval --provider anthropic --prompt v1
python -m lead_pipeline eval --provider anthropic
```

Показать матрицу ошибок и разницу между версиями промпта. Стоимость: Haiku 5.5, около
1,5 секунды и доли копейки на заявку, 80 заявок за полминуты в 4 потока.

## 5. Интеграции (20 секунд)

`NOTIFY_TELEGRAM=1` — сводка со срочными обращениями уходит в чат; `GSHEETS_ENABLED=1` —
таблица пишется на лист Google Sheets. Обе выключены по умолчанию, конвейер автономен.

## Частые вопросы

- **Почему structured outputs, а не «верни JSON» в промпте?** Схема проверяется на стороне
  API: не бывает лишних полей, неверных категорий и сломанного JSON, значит нет ветки
  «распарсить и починить».
- **Как меряете качество?** Золотой набор, размеченный вручную, с порогом в тесте, плюс
  разметка генератора на 80 синтетических заявках. Сравнение версий промпта на одном наборе.
- **Что с персональными данными?** Здесь всё синтетическое. В реальном проекте: договор об
  обработке данных с провайдером, минимизация полей, маскирование телефонов в логах.
- **Как масштабировать?** Message Batches API вдвое дешевле для тысяч заявок; очередь и
  повторные попытки по `error`; кеширование системного промпта.
- **Что бы улучшили?** Нормализация дат в календарные относительно `received_at`, CRM вместо
  таблицы, обратная связь менеджера как новые примеры для золотого набора.
